# dsh-bot 产品蓝图

本文描述从零重建的产品目标与业务规则，不描述实现路线：装配方式、文件格式、运行时安装与传输细节见[架构文档](ARCHITECTURE.md)，当前进度见 [README](../README.md)，概念定义见[术语表](../GLOSSARY.md)，上游证据见 [docs/research](research/)。旧版 Electron 产品规则已被本次决定替代。

## 产品定位

dsh-bot 是支持持续对话与工作管理的本机 Agent 工作台。用户选择具名 Bot，提交输入、查看执行过程并跟进工作目标。桌面 UI 是控制端，独立后台管理配置、工作区与执行状态；关闭或退出 UI 不停止已接纳的工作。

对话是连续聊天窗口，可以在同一消息流中容纳多段执行历史。对话是产品概念，不决定后台的执行结构，也不等同于上游执行会话。

## 对话模型

每个 Bot 只有一个持续对话入口，用户直接发送消息，不提供新建或切换会话的操作。首次打开时自动初始化底层执行上下文，之后继续使用已有上下文；初始化失败可以重试，重复请求不得创建额外上下文。已有多段历史仍在同一消息流中保留。

## Bot 与工作区

Bot 拥有稳定 ID、名称、归档状态、默认模型、思考级别、指令、能力选择和工作区。创建 Bot 时将模板默认值具体化写入该 Bot；之后修改模板不影响已有 Bot。

Agent 指令在内联内容与独立指令文件之间二选一，两者排他。显式重载时读取文件内容，创建执行时保存当时生效的内容；已有执行不自动追随 Bot 变化，空闲时才能显式应用新配置。保存的快照包含选择与内容，不冻结能力代码、凭据或全局设置。

每个 Bot 自动分配稳定默认工作区，也可以指向外部项目目录。同一 Bot 的多个执行默认共享文件，不自动复制目录，也不做并发隔离。工作目录不构成路径权限或操作系统沙箱；修改默认目录不移动既有执行。

归档 Bot 或配置缺失时禁止从该 Bot 新建执行；删除、移动或归档配置不删除历史、不清理工作区、不取消已接纳的工作。归档、取消工作、删除历史与清理磁盘各自独立。

## Bot 记忆

Bot 记忆按稳定 Bot ID 在该 Bot 的全部对话间共享，属于用户可维护的长期事实，不是自动摘要。用户可以查看、编辑和清空；每次保存携带版本号，过期编辑被拒绝。每次模型请求最多注入 2,000 个字符；来源与更新时间可见；首版不自动写入，也不检索历史生成记忆。

## 配置所有权

期望配置以配置文件为唯一权威来源，UI 与独立文本编辑器修改同一份内容。UI 只拥有主题、窗口和本地选择等偏好，不保存第二份权威 Bot 配置。模型密钥保存在系统凭据设施，配置只保存引用。

- 启动或显式重载时读取配置，第一阶段不做文件监听。
- UI 保存需携带读取时的内容版本；发现外部修改时拒绝覆盖，由后台原子写入。
- 无效重载保留已加载的有效配置并报告未生效内容；冷启动时无效 Bot 单独禁用，必要配置无效时保持可诊断而不执行。
- 影响进程资源的变化（如模型供应方声明）需要重启；Agent 的持久选择与动态设置分开处理。

## 输入、目标与状态

后台接纳输入时返回稳定请求标识，重试据此查找已接纳的工作；网络超时不能推断为未接纳。输入被接纳、执行进行、任务完成与工作目标完成是不同状态，目标是否完成由用户确认，不因执行结束而自动判定。

附件输入的完整用户消息会被持久化在本机，包含文本附件正文与图片数据，用于上下文重建与执行恢复，因此附件不是只存在于当前请求中；聊天视图另存用户输入与附件文件名、类型的投影，不含文本正文与图片字节。选择附件时 UI 必须告知这一持久化行为。

UI 断线不停止执行。停止当前工作、撤回尚未处理的输入与停止后台是三项独立操作。失败、中断与未确认的结果必须准确展示，不自动重发。

## 界面

客户端采用三栏：Bot 列表、对话、Bot 信息。消息区只展示用户消息与 Agent 文本，支持流式输出，不展示工具结构、工具结果卡片、推理过程或审批。Bot 信息区分 Bot 默认配置与当前执行的只读配置。

## 能力与扩展

能力只来自随包扩展与用户显式配置的本机工具服务；新发现的能力只进入选择器，不自动授予任何 Bot。只有 Bot 已显式选择的能力才能执行。

首版不提供逐次工具审批：需要审批的操作直接拒绝，不因缺少审批界面而默认放行。不支持远程或凭据型工具服务、任意脚本插件装载、多租户与服务端部署；外部工具进程不视为操作系统沙箱。计划模式不在本轮范围。

## 多端目标

未来桌面与 iOS/Android 客户端通过独立 Relay 跨网络同步。手机只发送和展示对话，不打包后台、不安装运行时、不运行执行引擎；移动端的密钥与令牌只存内存，每次冷启动重新验证，不写入安全存储或其他持久化位置。模型密钥只留在后台，多端通信不改变后台对执行状态的权威归属。

未来客户端需区分本机待发送、Relay 等待、后台已接纳与回答或拒绝状态；网络投递队列只负责投递，不替代执行侧输入队列。UI 断线或手机进入后台只影响自身同步，后台行为受移动系统限制。配对、撤销、迟到控制与多端可靠性仍需专项设计与验证。

## 验收范围

本机验收覆盖：配置文件初始化与重载、外部修改冲突保护、无效配置修复、指令快照、Bot 缺失、共享工作区、独立后台连接与重复启动排除、首次初始化与失败重试不产生额外上下文。

生命周期验收分别验证：UI 退出后继续执行、显式停止、重开恢复、独立取消工作与撤回输入，以及中断后的可恢复性遵循执行框架的公开契约。

验收必须如实标注范围：真实模型、移动端、其他平台与签名交付分别报告，不从旧测试或开发环境结果推导。真实模型调用与中断工具恢复目前尚未验收。

## 范围外

多端正式交付、外部消息渠道、定时触发、主动推送、多后台调度与迁移、自动记忆整理与检索、自动跨 Bot 协作、群组、开机自启均不在本轮范围，另行设计与验收。
