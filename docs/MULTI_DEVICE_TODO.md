# 多端接入待办

当前配对、设备授权、加密通道和 Relay 均为实验性基础，尚不能让手机读取或继续 Bot 对话。桌面二维码界面不代表移动端已经可用。产品规则以 [BLUEPRINT](BLUEPRINT.md) 为准，职责与权限边界以 [ARCHITECTURE](ARCHITECTURE.md#9-多端与-relay) 为准。

## 待实现

- **移动客户端与设备身份**：先实现 iOS，再实现 Android。接入扫描一次性邀请、显示用于桌面核对的设备指纹、配对结果与撤销后的恢复；设备私钥分别由 Keychain / Keystore 保护。接入官方客户端的 unary 和流式 transport；不在手机上安装 dsh 或维护第二份会话状态。
- **Host Bridge 到 dsh 的业务连接**：实现配对后的设备连接发现、每设备独立上游认证与 Peer，绑定设备授权及 dsh generation，转发官方协议并提供只读 Bot 快照。设备撤销、Host 退出或 generation 更换须取消并清理该设备的连接和在途任务。认证凭据不发送到 Relay 或手机。
- **授权与恢复**：在每次请求和订阅中校验设备、最新 Bot 与 Session 归属、请求参数和归档状态；补齐历史分页、游标、下行事件和审批答复的安全过滤。不能向手机直接暴露 owner 的全局事件流。明确撤销、归档与并发提交的边界；未确认输入保留稳定请求标识，断线后核对事实，不自动重发。
- **本地与公网 Relay**：提供手机可访问的本地安全连接方案，验证地址、TLS 信任、连接发现和端口配置；本机 `127.0.0.1` 不可作为手机的目标地址。公网部署、证书、限额及可用性另行验收；Relay 只转发密文，不持 owner 凭据。
- **Host 模块接口**：梳理 `apps/host/src/bridge` 的对外导出，把设备存储、配对与传输的内部实现收敛到明确接口，同时保留有效的集成测试边界；这是审查提出的设计改进，需结合实际调用者落实。

## 验收

- 在隔离数据根、独立 Relay 和真实官方 dsh 上验证：桌面创建 Bot 并开始对话后，手机读取同一历史并继续对话；覆盖断线恢复、历史分页、审批、撤销及归档竞态，确认未授权设备和其他 Session 无法访问。
- 分别验证 iOS 真机的二维码、Keychain、前后台切换及重连，再验证 Android 的扫码、Keystore 和生命周期；本机协议测试不能替代真机验证。
- 验证 Relay 无法读取消息与认证凭据，大消息分片及背压有界；结果未知的写请求不因重连而重发。分别报告本地、公网、真实模型和签名交付的验证范围。
