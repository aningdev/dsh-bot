# 界面设计与文案规范

适用于桌面、后续 Web 应用及共享 UI。优先通过 shadcn 主题 Token、组件公开属性和页面布局落实规范。共享组件的必要修改集中在 `packages/ui`，保持组件更新流程可维护。

本规范是界面开发与评审要求，不表示现有界面已全部完成整改。

1. **文案准确、简洁。** 使用目标用户容易理解的产品术语，避免开发术语、过度口语化、随意造词及重复表达。同一概念保持同一名称；按钮描述操作，标题标识内容，状态说明事实。

2. **只保留必要说明。** 不添加复述标题、按钮功能或显而易见行为的解释。说明文本用于交代必要条件、操作影响、错误原因与恢复方式，并放在相关位置。文案不使用中点 `·` 作为分隔符，优先通过布局与间距组织并列信息；用户内容和代码不受此限制。

3. **统一使用 shadcn 语义 Token。** 页面和自定义组件使用 `background`、`foreground`、`muted`、`accent`、`border`、`ring`、`destructive`、`chart-*` 等现有 Token，不直接填写颜色值或使用具体色板类名。主题值由 `packages/ui` 统一维护，覆盖明暗主题。新增语义 Token 前先检查现有 Token 是否适用；状态信息同时通过文字或图标表达。品牌标识、用户内容和代码高亮主题保留自身颜色。

4. **保持视觉对齐。** 同行文字、图标与控件保持稳定的基线和视觉中心，结合图形留白进行光学校正。相同层级统一间距、控件高度与内容起点，避免仅靠容器居中造成视觉偏移。

5. **沿用现有圆角体系。** 优先使用 shadcn 组件与现有 `--radius` 派生规格。自定义嵌套容器的圆角与内缩距离保持协调，尽量形成同心圆关系。避免无目的的卡片嵌套，不另建圆角体系。

6. **克制使用边框。** shadcn 组件保留默认边框与焦点 ring。应用自定义分隔线和面板边界优先使用 `0.5px`，通过语义 Token 控制对比度。避免叠加边框或使用粗边框制造层级，键盘焦点必须清晰可见。

7. **减少阴影与装饰。** 优先通过背景、间距、排版和留白区分区域。页面不新增装饰阴影或卡片左侧彩色竖线；弹层保留组件已有的层级表达。

8. **减少额外动效。** 保留 shadcn 组件必要的交互动效，不额外添加装饰性入场、悬停位移或重复过渡。新增过渡优先使用 `ease-out`，时长参考 `150–250ms`，仅指定必要属性，避免 `transition-all`；遵循系统减少动态效果的偏好。

9. **控制字号层级。** 应用自定义文案优先使用 `12px`、`14px`、`18px` 三档字号，单个页面及其弹层最多四档，不新增小于 `12px` 的正文或操作标签。优先通过字重、语义文字颜色、间距和留白补充层次。shadcn 内部辅助元素沿用现有规格，出现可读性问题时集中修正共享组件。

10. **围绕主要任务组织交互。** 突出当前主要任务，相关操作靠近作用对象，降低次要操作的视觉权重。减少无必要的确认、重复选择和中间步骤；必须由用户判断的选项，放在用户准备作出选择的位置。破坏性或难以撤销的操作保留必要确认。

11. **克制使用眉题与标签。** 默认不在标题上方添加装饰性眉题或英文大写标签。仅在提供标题未表达的分类、上下文或关键状态时保留，避免语义重复。优先通过排版和留白建立层次。

12. **集中维护并验证。** 不通过全局 CSS 强制重置所有 shadcn 组件的边框、字号、圆角或动效。共享组件修改只解决已确认的问题，并检查组件更新对定制的影响。界面调整需验证明暗主题、键盘焦点、主要交互状态及桌面成品。
