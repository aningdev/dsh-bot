# dsh-bot 产品蓝图

本文描述从零重建的目标，不表示所有能力已实现。当前进度见 [README](../README.md)，工程边界见 [PROJECT_LAYOUT](PROJECT_LAYOUT.md)，完整决策来源见 [NSH_REBUILD_PLAN](NSH_REBUILD_PLAN.md)。旧版 Electron 产品规则被本次决定替代。

## Bot 与会话

用户通过具名 Bot 协作。Bot 保存名称、默认模型、指令、能力和默认工作目录；一个 Bot 拥有多个独立会话，每个会话对应一个 Harness Session。创建会话时具体化配置并固定工作目录，之后不允许修改执行配置。Bot 默认配置更新只影响新会话。恢复已有会话不能静默套用最新 Bot 默认值。

配置快照不复制模型密钥或冻结插件代码、引擎版本。目录选择不是授权或沙箱，也不自动建立 Git worktree。

## 简单对话界面

NSH TSX 客户端采用三栏：BotList、BotChat、BotInfo。中间顶部选择或新建会话，消息区只展示用户消息与 Agent 文本，支持流式输出；不展示工具结构、工具结果卡片、推理过程或审批。右侧区分 Bot 默认配置和当前会话只读配置。

普通发送默认排队，显式追加使用 Harness steer。停止当前执行、撤回待处理输入与停止后台分别处理。失败、中断和未收到接纳确认的结果未知必须准确展示，不自动重发。

## 后台与权限

Node Runner 独立于客户端存活，通过认证接口访问。关闭窗口不停止已接纳工作；异常重启恢复历史，不自动重放输入或继续未完成工具。用户主动停止后台后保持停止，登录自启是独立可选设置。

首版使用 DeepSeek 官方 API，凭据只存于后台并复用 Harness 凭据机制。客户端可以提交密钥和查看配置状态，不能读回已保存密钥。

能力采用内置组合，首阶段最小实验只启用文本、不加载工具。后续能力必须满足无需交互审批的策略；需要审批的操作直接拒绝，不因没有审批界面而默认放行。

## 交付与范围

先完成 macOS 本机闭环，早期用移动端最小页面验证通信。使用 NSH 官方预编译运行时，不维护自定义 Rust；安装包携带 Node 和后台依赖，用户无需另装开发运行时。客户端与后台统一发布，后台不独立自动升级。

旧源码、旧测试和旧构建链全部删除，旧分支保留用于回顾；不迁移旧数据。新验证围绕已确认行为建立。远程配对、Relay、完整移动产品、附件和插件市场另行设计。
