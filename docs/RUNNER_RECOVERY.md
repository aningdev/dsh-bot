# Runner 崩溃恢复

当前实现覆盖 #13 的崩溃恢复及本机手动应用随包更新。下载、发布与无人值守更新不在当前实现内。

## 当前行为

用户级 LaunchAgent 通过 `KeepAlive` 拉起意外退出的 Runner。新进程生成新的实例身份和连接资料，Main 在下一次请求时重新认证；不复用旧实例的连接。

Bot 恢复复用 Harness 的 Session JSONL 修复机制。未结束的轮次补记 `turn/end` 的 `interrupted` 原因；未返回的工具调用补记保守错误结果，恢复代码不重新执行工具。标准 inbox 恢复保留未处理消息，但读取状态、历史和工具活动不唤醒驱动。

Bot 的 `inputState.interrupted` 从最后一轮的持久结束原因计算：意外中断或生命周期释放导致的取消在空闲状态显示中断提示，用户主动停止不归入该提示。桌面重新打开后仍可显示。用户查看记录并撤回保留输入后，可主动发送新请求；完成新轮次后提示消失。已有发送观察断流不会自动重发。

此状态复用标准 Session 日志，没有新增产品恢复日志、消息队列或工具执行器。未完成配置事务仍沿用原有故障保护，不会因崩溃恢复而绕过。

- `apps/desktop/tests/e2e/runner-service.test.ts` 使用成品随包 Node 和真实用户 launchd，SIGKILL 后验证新实例连接资料产生，并可停止和卸载。
- `apps/desktop/tests/e2e/bot-recovery.test.ts` 在确定性工具等待结果期间 SIGKILL 真实 Runner 进程；用同一 home 重启 Runner、重新打开打包桌面，验证中断提示、未重复用户消息、保留输入及主动恢复。模型与工具为测试适配器；此用例不声称经过 launchd 重启，launchd 由前一用例单独验证。

- 本机工作区单元测试 95 项通过（Bot 33、Runner 20、桌面 42）；工作区检查 0 错误、6 项已有 UI 警告；成品 IPC 与迁移后的随包 Runner 冒烟通过。

## 应用随包更新

安装时，Main 将随包资源复制到 `<home>/service/runtimes/<sha256>`，复制完成并校验内容后才发布目录。摘要覆盖实际文件、大小、可执行权限与相对链接，包含产品代码，不仅依赖锁文件。正在运行的后台从该独立目录加载；更换或移动 `.app` 不会改写它的依赖。旧版本保留，不自动删除。

安装新桌面版本后，打开「后台服务」并点击「更新后台」。操作先 `bootout` 移除 job，等待 job 卸载及先前 PID 消失，再准备当前桌面携带的运行时并原子更新启动配置。原先运行的服务重新 bootstrap，并等认证后的 Bot 列表读取成功才报告更新成功；原先已停止的服务保持停止。登录启动偏好保留。

停止、复制、启动或认证失败均报告更新未完成。复制失败不会覆盖已安装版本；停止后发生失败时不自动重启旧任务，不自动重发输入或重跑工具。后台日志和中断状态仍可检查。该流程没有自动运行时回滚、在线下载或数据格式降级能力。launchd 的退出宽限为 30 秒，超时可能强制终止；PID 消失只证明进程退出，不证明每个外部工具完成了清理。

验证覆盖实际成品 Node、用户 launchd、版本目录切换、关闭和重开桌面；确定性边界测试覆盖旧进程仍存活时禁止准备替换、保留登录偏好、已停止状态，以及复制失败后保持停止和旧启动配置。升级阶段桌面单元测试 44/44 通过；全量 E2E 29/30 通过，唯一失败仍为既有原生全屏超时。最终工作区检查 0 错误、7 项已有警告，重新打包和成品 IPC/迁移后 Runner 冒烟通过。独立 reviewer 再次因上述旧 Node 路径失效而未启动，此阶段由主代理复核。真实模型和工具、干净目标机、实际登录及人工安装升级验收仍待完成，不能据此关闭整个 #13 或宣布首版交付。
