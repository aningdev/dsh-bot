# Runner 由用户级 launchd 管理，独立于桌面存活

状态：后台独立于客户端的产品要求继续有效；以下 Electron 安装、签名和升级机制属于旧实现。NSH 重建的后台托管与打包仍须按 [新方案](../NSH_REBUILD_PLAN.md) 验证。

执行状态必须比交互窗口活得更久：退出桌面不能中断已接纳的工作，Runner 异常退出后还要能自行恢复。如果由 Electron 主进程持有 Host，窗口关闭、崩溃或升级都会带走执行，且桌面之外的第二台设备就无从连接。

因此 Runner 是独立的用户级 LaunchAgent，由 launchd 负责启动、异常拉起和可选的登录自启；Electron 主进程只负责连接、显示状态和请求启动或停止。用户主动停止 Runner 后它保持停止，直到再次启动或满足已启用的登录自启条件。自动重启不重放输入，也不重复执行工具。

代价是后台进程需要随应用分发自带运行时，并处理用户级安装位置与签名。升级由桌面安装包统一驱动：先有序停止 Runner，替换运行时后由 launchd 重新拉起，进行中的工作按恢复规则处理；两个版本不会分头升级。这些都需要在真实安装包上验证。相关依据见 [架构与工作区方案](../PROJECT_LAYOUT.md)。
