# 以 npm 发布版消费 Harness，而非在上游工作区内开发

dsh-bot 需要自己的 UI、Bot 规则、后台进程和交付流程，而上游 Harness 仍在频繁演进。把产品代码放在上游工作区会持续承担上游的构建、依赖和测试规则差异；把上游源码作为产品构建输入则要同步并定制整套工程。

因此本仓库独立存在，引擎与插件通过精确版本的 npm 公开入口消费，上游源码只作为固定提交的 Git submodule 供阅读和兼容性研究，不进入产品构建。上游跟进由此变成依赖升级与兼容验证，而不是持续合并。

代价是公开接口的可用性必须在升级时逐项验证，必要时保留最小补丁或明确版本的兼容包。相关依据见 [架构与工作区方案](../PROJECT_LAYOUT.md) 和 [Host 与客户端调研](../HOST_AND_CLIENT_RESEARCH.md)。
