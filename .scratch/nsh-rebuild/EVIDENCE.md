# NSH 单机重建验收记录

本地实施记录；不发布 GitHub、不提交或改写 Git 历史。01–05 已实现并完成本机验收；06 的代码、入口清理与构建检查完成，成品 GUI 操作验收受锁屏阻挡，仍保留待办。

## 环境与依赖

- 官方后台：`dsh 0.2.1-rc.5`，由用户安装的官方 CLI 提供；客户端公开 npm 依赖精确锁定同一发行版。
- NSH：本机 `0.2.0`；客户端运行于 NSH，通过 Rust 原生 HTTP/WebSocket 传输复用公开 npm 客户端协议。
- 根目录唯一 `bun.lock`；`bun install --frozen-lockfile` 通过且未产生更改。
- `references/` 仅供研究；未修改子模块，不进入产品安装、导入或打包。

## 场景覆盖

1. Bot 原子登记；首次打开就绪 Bot 自动初始化唯一 Session；普通文本及 Agent 流式文本展示。
2. 初始化期间编辑草稿，正式指针提交后及关闭重开后仍保留；初始化后改名保留 Session 指针。
3. 不存在的工作区可先保存；修复入口遇到无效模板不写入初始化意图，改回有效模板后仍能完成初始化。
4. 后台创建已完成但响应丢失，按持久候选标识核对并复用；正式指针保存失败后修复，不重复创建。
5. 模板缺失与恢复失败分类显示，保留原有记录与指针，阻止错误发送。
6. 排队、撤回、停止保留队列、审批拒绝和取消；归档保留既有工作。
7. 审批跨客户端关闭重开恢复；已取消请求不能继续答复。
8. 发送结果未知时保留 requestId 与草稿，核对后台是否接纳，不自动重发。
9. 当前对话模型切换与恢复，保留初始化默认模型与后台当前模型的区别。
10. 供应商 schema 字段适配、凭据写入和移除、不回显；第二个真实客户端制造 revision 冲突，验证不覆盖后台，重新读取仍保留编辑草稿。
11. 在隔离 DSH_HOME 中将凭据文档路径改为目录，使真实 credentials provider 写入失败：界面分别报告配置已保存、密钥提交未确认；清空密钥输入，不回显密钥，不回滚已保存配置。

launchd 真实进程、日志代际、启停、异常恢复及版本检查的先前验收证据见 [05](issues/05-launchd.md)；连通协议证据见 [01](issues/01-connectivity.md)。

## 审查修复

按仓库规范与已确认规格进行复审，并修复了以下问题：

- 凭据保存捕获固定引用，保存期间禁止修改表单；native-auth 供应商固定使用其声明的凭据引用。
- 初始化统一模板预检；正式指针提交时合并最新登记，保留初始化期间的草稿、名称与归档修改。
- 冲突刷新先保存本地编辑，再读取后台基线与 revision；需要用户核对并再次保存，不自动覆盖。
- 就绪 Bot 在首次打开时自动初始化；测试不再用首次发送代替首次打开验收。
- 审批只注册一次 Agent 客户端上下文，使用订阅生命周期清理失效请求；历史和队列依据公开协议投影。

新增与修订的回归测试均已纳入最终通过的 `test:e2e`。

- **签名范围**：仅本机 ad-hoc 签名及签名校验；未作 Developer ID 签名、公证与外部分发验收。
- **平台范围**：本机 macOS；未验收 Intel macOS、移动端或其他系统。
- **后续功能**：bridge/Relay、多端、独立指令和记忆、附件、模板编辑器等仍在后续阶段。

所有验收后台与数据均使用隔离环境；临时 GUI 验证进程在测试后关闭，不留下测试 LaunchAgent。正常运行使用 `bun run dev`，或启动上述 `.app`；依赖已安装的受支持官方 `dsh`。
