# NSH 单机重建实施规格

状态：已确认，按用户要求在本地执行，不发布 GitHub。依据已经确认的产品蓝图、架构及 18 项取舍整理；本文不新增产品决策。

## Problem Statement

用户需要一个可持续对话的本机 Bot 工作台，关闭窗口后已接纳工作继续，重开能够恢复状态。当前代码仍依赖产品自建 Runner、Bot 服务、REST 与拼装运行时，和已经确认的官方 dsh web 方案不一致。旧 GitHub spec #1 及其子任务描述旧方案，不能直接作为新实现要求。

## Solution

交付 NSH 桌面客户端，连接用户安装的官方 dsh web。后台由 launchd 托管，承载全部 Bot 的执行；桌面管理 Bot 注册表、持续对话、审批和共享模型设置。先证明公开产物在实际 NSH 运行时中可连通，再逐步替换旧链路并验收 macOS 成品。

## User Stories

1. 作为用户，我想创建具名 Bot，选择已安装模板与工作区，从而获得一个稳定的对话入口。
2. 作为用户，我想先保存尚未就绪的 Bot，按明确提示补齐后台、模型、模板或目录，从而不丢失已经填写的信息。
3. 作为用户，我想每个 Bot 自动获得稳定默认工作区，也能初始化前指定外部项目，从而选择在哪里执行。
4. 作为用户，我想首次打开就绪 Bot 时自动初始化，从而不必管理执行会话。
5. 作为用户，我想初始化结果未知时先核对后台，从而避免意外创建多条历史。
6. 作为用户，我想重开 Bot 后恢复原对话，从而连续跟进工作。
7. 作为用户，我想明确看到模板缺失、历史损坏或会话不存在的原因，从而自行修复或另建 Bot。
8. 作为用户，我想初始化后保持模板与目录固定，从而避免原对话悄悄改变执行环境。
9. 作为用户，我想知道模板在后台重启后使用当前定义，从而不误以为旧模板代码永久冻结。
10. 作为用户，我想发送纯文本并看到流式回复，从而及时掌握工作进展。
11. 作为用户，我想执行中发送的消息排入下一轮，并可撤回尚未领取项，从而调整后续工作。
12. 作为用户，我想发送结果未知时保留内容并重新核对，从而避免重复执行。
13. 作为用户，我想普通草稿与未确认输入在重开后仍存在，从而恢复未完成操作。
14. 作为用户，我想停止当前执行但保留队列，从而决定后续继续还是逐条撤回。
15. 作为用户，我想区分取消请求已接纳与执行已经停稳，从而理解并发输入下的状态。
16. 作为用户，我想审批时看到工具、操作摘要和关键目标，从而作出有依据的允许或拒绝。
17. 作为用户，我想关闭窗口后审批可以等待重连，从而不必保持界面在线。
18. 作为用户，我想归档 Bot 隐藏默认列表但保留历史和既有工作，从而整理助手而不丢失记录。
19. 作为用户，我想在归档区处理审批与待处理输入，从而完成已经接纳的工作。
20. 作为用户，我想集中配置共享供应商、模型目录与凭据，从而不为每个 Bot 重复设置。
21. 作为用户，我想设置冲突时保留草稿并重新读取，从而避免覆盖他人或后台的新配置。
22. 作为用户，我想密钥只提交、不回显、不进入客户端文件或日志，从而减少机密副本。
23. 作为用户，我想初始化前选择默认模型、初始化后切换当前对话模型，从而理解操作影响范围。
24. 作为用户，我想模型不可用时保留原选择并明确报错，从而主动修复而不被静默切换。
25. 作为用户，我想桌面退出后已接纳工作继续、重开恢复，从而不用守着窗口。
26. 作为用户，我想可以显式停止后台并查看启动失败，从而确定后台是否在运行。
27. 作为用户，我想不兼容版本阻止发送并保留草稿，从而获得明确修复路径。
28. 作为维护者，我想使用公开发行产物完成验收，从而避免参考源码与实际运行包的差异被掩盖。

## Implementation Decisions

- 执行后台为未经修改的官方 dsh web，使用共享 web profile 和独立产品数据根；不注入产品 Host 服务、Agent Loop、自有 bundle 或每 Bot 插件环境。
- 模型循环、队列、日志、模板注册、审批与模型设置沿用上游。客户端只负责交互、Bot 注册表和传输适配。
- 用户安装官方 dsh；产品不随包分发 Node，也不自建运行时解析。直接使用的 Harness npm 依赖锁定同一实测发行版。
- 桌面独占写 Bot 注册表，原子保存稳定身份、名称、模板引用、工作区、默认模型、归档状态与唯一 Session 指针。
- 初始化前持久保存候选 Session 标识及恢复信息；串行初始化，结果未知先查询后台。正式指针保存成功后才允许输入。
- 初始化后固定模板与工作区。运行实例保留已装配组合；后台重启后按模板 ID 读取当前定义，缺失或无效时报错。
- 使用 token 引导与服务返回的 Cookie。HTTP、认证 WebSocket、流、取消与断线均通过实际 NSH 验证；传输适配保留后续替换入口。
- 后台发现从当前启动的 ready 日志获得，并验证连接与实际版本；旧 ready 行不能当成当前事实。
- 普通输入使用上游 next-turn 队列。输入提交前保存请求标识及正文；未知结果不自动重发，不提供一键重试。
- 停止使用上游保留 inbox 的取消语义。取消请求被接纳不代表已停稳；竞争输入可能再次唤醒，不能承诺持续暂停。
- 普通消息只展示用户与 Agent 文本；审批单独展示工具、摘要、关键目标与允许/拒绝。无 UI 时允许等待重连，不静默放行。
- 归档阻止新输入，保留已经接纳的工作与审批，不删除历史或工作区。
- 模型设置经上游 settings 与 credentials remote 保存。revision 冲突不覆盖，机密不回显或落盘客户端；分步保存分别报告结果，不声称跨调用事务。
- Bot 默认模型用于初始化；当前模型来自后台记录，切换从下一执行步骤生效，已准备步骤保留原选择。错误保留选择，不静默回退。
- 首版只支持一个经实测的发行版。预检发现本机为 dsh 0.2.1-rc.3、NSH 0.2.0 (68531fb)，尚不能据此认定整套兼容性通过。
- 旧产品链路通过新路径验证后移除，不移植旧专用测试；保留用户未提交内容和只读参考子模块。

## Testing Decisions

以下边界来自已确认架构的阶段验收，任务发布前确认覆盖范围。

1. **实际 NSH 客户端到官方 dsh web 的公开协议。** 在隔离数据根中启动官方进程，通过真实 NSH 网络能力验证认证、HTTP、WebSocket、事件流、审批、取消与重连。覆盖跨运行时和协议差异；不证明 launchd、真实模型质量或移动系统行为。
2. **桌面用户操作到持久恢复的可见行为。** 经客户端入口创建/打开 Bot、发送、排队、停止、审批、配置保存、重开恢复，断言界面结果与公开后台读回状态。必要时使用独立的本机 OpenAI 兼容确定性测试服务；不向产品后台注入测试插件。覆盖用户闭环及失败恢复；不证明真实供应商或正式签名交付。
3. **macOS 成品与生命周期脚本的外部行为。** 验证实际 LaunchAgent 安装、启停、异常退出、当前日志发现、窗口关闭后继续和重开恢复。覆盖进程及成品依赖；登录行为与正式签名范围分别报告。

每次只围绕一个可观察行为走失败到通过的循环，不断言私有字段或内部调用次数。连通未通过前保留可运行旧链路。真实模型另行验收，不用确定性服务替代真实调用结论。

## Out of Scope

- bridge、Relay、移动端、多端配对及加密协议实现。
- 独立 Bot 指令编辑/重载/快照、Bot 记忆、附件。
- 模板编辑器、永久删除、磁盘清理、独立目标管理、执行中立即插入。
- 开机自启产品功能、多后台调度与迁移、服务端部署。
- Intel macOS、其他桌面平台、Developer ID 签名与公证交付。
- 改动上游执行框架、重写 Git 历史、关闭或重写旧 GitHub spec 与任务。
