# Rust 宿主约束

本文件补充[根约束](../../AGENTS.md)。修改宿主、后台服务登记与控制、迁移升级或 macOS 打包时适用，客户端与脚本调用方同样遵守。职责与迁移条件读[架构文档](../../docs/ARCHITECTURE.md)的「装配与启动」「本机宿主控制通道」「打包与交付」；产品行为以[蓝图](../../docs/BLUEPRINT.md)为准。

## 模块与生命周期

- `DshProcess` 独占 dsh 生命周期策略与进程资源，公开入口为 `Lifecycle`；启动、并发启动归并、监控、失败预算、停止与回收收拢在 `dsh_process/`。内部锁、guardian、环境与日志辅助实现保持私有，控制通道和监控线程通过公开 Interface 操作。
- `HostControl` 在 `host_control/` 提供本机管理、连接发现及共享控制协议；只调用 `Lifecycle`，不直接访问进程锁或 guardian，不另建启动、重启与回收策略。业务 remote 仍由客户端直连 dsh，控制 socket 只承载宿主管理与生命周期状态。
- `main.rs` 只装配与分派，`lib.rs` 保留客户端原生适配所需的共享控制 Interface 导出；`run_guardian` 仅供可执行入口分派。领域内代码增多时拆入对应目录的私有子模块，公开入口保持集中。
- 控制协议的请求、响应与帧校验集中在 `host_control/protocol`，客户端原生适配复用共享契约。修改协议同时核对宿主接收、客户端解码、状态订阅与失败语义，公开状态与认证连接信息保持分离。

## 后台身份与服务操作

- UI 退出不停止已接纳工作；首次打开只查询状态，用户明确启动才申请后台运行。系统禁用后保留数据与修复入口，恢复批准后仍等明确启动，不绕过系统状态；首版不提供开机或登录自启。
- 目标通过 `SMAppService` 注册 App 内辅助程序，服务入口直接执行辅助程序。NSH TypeScript 决定登记、批准与明确启动的产品顺序，客户端 Rust 仅返回系统调用结果与 OS 状态；宿主负责 dsh 运行生命周期。
- 旧 LaunchAgent 仅隔离在客户端 TypeScript 的 `legacy-backend/` 临时兼容，不新增产品规则或迁入宿主。切换条件按架构文档执行，停止并卸载旧服务、确认旧进程回收后才接管，保留数据与草稿。
- 升级按蓝图等待后台空闲，空闲判断包含活动执行、待处理输入与待审批请求；立即中断须明确确认。确认停止与进程回收后才替换，保留 Session、队列及核对记录；恢复遵循升级前运行状态与系统允许状态，不补发输入或自动答复审批。

## 联调与成品验证

- 生命周期与协议修改验证隔离宿主进程；影响共享导出、发现或控制通道时，还须验证实际 NSH 原生绑定与宿主联调。脚本只调用公开控制入口，避免维护另一套 spawn、日志发现或重启逻辑。
- `SMAppService` 的注册、批准、禁用、注销、重新登录与升级迁移须以实际成品核验。系统名称、图标与归属以签名成品实测为准；Rust 测试、注册成功或 ad-hoc 包不能替代应用关联服务实际启动与签名交付验收。
